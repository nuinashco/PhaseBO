# AGENTS.md

Bayesian optimisation for accelerated exploration of phase fields. Architecture and extension recipes:
[CONTRIBUTING.md](CONTRIBUTING.md). Conventions and their reasons: [CONVENTIONS.md](CONVENTIONS.md), a read-only
copy of the conventions guide.

Before committing a change that adds or moves modules, configs, tests, entry points or docs, run the
`conventions-reviewer` subagent (`.claude/agents/`) and fix its MUST findings. `.claude/settings.json` runs
`check-protected` before each edit (files `.gitattributes` marks `protected` are changed at their source),
`check-comments` after it and `review-comments` before you hand back; fix what they report.

## Commands

```bash
make setup          # uv sync + git hooks (pre-commit, commit-msg)
make check          # ruff, import contracts, pyright, pytest: must pass before every commit
make format         # ruff fixes + format
make configs        # regenerate configs/ after changing any config schema
phasebo-suggest     # next compositions to compute; results in runs/<run_name>/
phasebo-benchmark   # BO replayed over the computed compositions
phasebo-generate    # candidate compositions of the phase field
make data           # check data/processed/ against data/raw/; scripts/process_*.py rebuild it
```

## Layout

- `src/phasebo/cli/`: one module per console script; the only place objects are wired together. `_launch.py` holds
  the commands' start-up and the adapters to the pre-template class.
- `src/phasebo/phase_field.py`, `phase_field_bo.py`: pre-template code, excluded from ruff, pyright and pre-commit
  until it is rewritten (CONTRIBUTING, Deviations). Don't extend it; new code goes into families.
- `src/phasebo/table.py`: the canonical processed table, a pandera schema; `processed.py`: its files and sha256
  sidecar (pydantic);
  `candidates.py`: candidate generation.
- `scripts/`: exploratory or one-time runnables, never imported; they may import the package and compose
  `configs/`. Anything `make`, CI or a test depends on is a `cli/` command; a script that is rerun or shared becomes
  one.
- `src/phasebo/config.py`: entry config schemas; `paths.py`: repository paths.
- `src/nuikit/`: shared machinery (config base, YAML generation, registry, errors, logging, runs, seeding), copied
  from the conventions template. Change it there and `copier update`; never edit it here.
- `configs/`: Hydra YAML. Files starting with `# Generated by` (`defaults/`, `kinds/`) mirror schemas: never edit them
  by hand. `configs/<command>.yaml` are the hand-written entry configs; `configs/system/` holds the phase fields.
- `data/raw/`: published datasets, never edited. `data/processed/`: written by `scripts/process_<source>.py` with a
  sha256 sidecar, committed; never edit it by hand, rerun the script.
- `tests/` mirrors `src/`; `tests/test_invariants.py` holds the repo-wide checks.

## Rules that tools do not check

- Configs: every tunable value has a default on a schema; no tunable constants in code. A `description` only lists
  the options or says what the name can't: units, what `null` means, side effects (DOC-7).
- Classes: attrs (`@frozen` values, `@define` stateful) everywhere except config schemas (pydantic). No hand-written
  `__init__`; derive state in a classmethod constructor.
- Families: `base.py` + `items/<kind>.py`; `@Factory.register("kind")` goes above `@define`.
- Each seam has a pure half that decides and an effectful half that acts.
- Branch on capability flags (`ClassVar[bool]`), never on `kind ==`.
- Errors the user can fix raise `UserError` subclasses with lowercase messages: what is wrong, `; `, the fix.
- Logs are structlog events: `log.info("snake_case_event", key=value)`; user-facing output uses `click.echo`.
- Comments say only what the code cannot: constraints, reasons, units, provenance. One-line docstrings, imperative.
- Randomness: take an explicit `np.random.Generator`; `seed_everything` runs once in the entry point.
- Tests: pytest functions named as sentences, in-process fakes, one distinct behaviour per case.
- Commits: one line, `type(scope): imperative subject`, standard types, no articles, no body or trailers. Docs change
  in the same commit as the code.
